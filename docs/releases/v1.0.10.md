# Code Intel v1.0.10

## Overview

Version 1.0.10 delivers five coordinated changes:

1. **Generation V2** keeps atomic index publication and rollback safety while eliminating unnecessary generation work and mixed-generation reads.
2. **Agent-aware setup** makes `code-intel setup` respect the agents selected by the existing analysis flow and prevents setup from polluting repositories with unrelated agent files.
3. **Embedding model selector** replaces free-text model configuration with a backend-authoritative catalog that drives runtime model loading and vector dimensions.
4. **Persistent remembered sessions** keep valid Remember-me logins authenticated across `code-intel serve` restarts without persisting raw cookie credentials.
5. **Resilient GQL query results** normalize every successful GQL response and prevent aggregate-only query results from crashing the Query Console.

The release branch is `release/1.0.10`.

## Generation V2

### True no-op analysis

A healthy analysis with no relevant source or index changes now returns before staging creation. It preserves:

- the active generation ID;
- the exact bytes of `.code-intel/current.json`;
- the published generation count;
- graph, BM25, vector, and metadata artifacts;
- the absence of `.staging-*` directories and `analyze.lock` after completion.

Unrelated Git changes such as generated JSON reports are ignored by source-change planning. Tracked, staged, unstaged, untracked, mtime-changed, and deleted files are considered only when they are supported source files or paths represented in the previous source snapshot.

### Selective staging

The parent process resolves an analysis plan before creating staging. A changed repository still uses a correctness-first full graph/BM25 rebuild, but a healthy vector index is cloned only when incremental vector delete/upsert work needs its previous state.

Artifact cloning attempts:

1. forced filesystem reflink;
2. normal reflink;
3. physical copy fallback.

Verbose analysis output reports the selected work modes, seed artifacts, and clone modes.

### Serialization and staging safety

Repository analysis is serialized through:

```text
.code-intel/analyze.lock
```

The lock records owner token, PID, hostname, start time, base generation, and staging generation. A live process remains the owner regardless of elapsed time. Dead same-host owners can be recovered safely; unverifiable cross-host locks fail closed.

Each staging generation contains ownership/activity metadata. Cleanup preserves active and recent staging and removes only abandoned stale staging.

### Pinned snapshots

Graph, BM25, vector, and metadata reads can now use one immutable `IndexSnapshot`. Storage helpers, index trust, scoped search, repository groups, MCP, and HTTP loading paths use cohesive generation paths instead of resolving `current.json` independently for each artifact.

An operation that starts on generation A completes on A even if generation B is published during the operation. Later operations can resolve B.

### Manifest and compatibility

Generation V2 manifests add versioned generation, base-generation, schema/parser, and artifact detail fields while preserving the v1-compatible top-level fields.

The release remains compatible with:

- generation-v1 manifests;
- existing generation directories;
- legacy flat `.code-intel/graph.db`, `bm25.db`, `vector.db`, and `meta.json` layouts.

Legacy flat files are never deleted automatically.

### Maintenance commands

```bash
code-intel index cleanup [path]
code-intel index cleanup [path] --dry-run
code-intel index cleanup [path] --keep 2
code-intel index cleanup [path] --stale-hours 24
code-intel index cleanup [path] --remove-legacy
code-intel index unlock [path]
code-intel index unlock [path] --force
```

Configuration defaults:

```json
{
  "index": {
    "keepGenerations": 2,
    "staleStagingHours": 24
  }
}
```

Cleanup never removes the active generation. Explicit legacy removal requires a valid trusted active generation.

## Agent-aware setup

`code-intel analyze` remains the owner of repository instruction files. The first interactive analysis saves the selected agents in:

```text
.code-intel/agent-targets.json
```

`code-intel setup [path]` reads that selection, configures MCP independently, and installs only supported global integrations mapped to selected agents.

Setup no longer creates or updates repository instruction files such as:

```text
.cursor/**
.github/**
.kilocode/**
.agents/**
.clinerules
.windsurfrules
AGENTS.md
CLAUDE.md
```

Existing files are preserved.

Supported modes:

```bash
code-intel setup [path]
code-intel setup [path] --mcp-only
code-intel setup [path] --all-agents
code-intel setup [path] --dry-run
```

Missing or invalid selection fails closed and never falls back to every agent. This release does not add `code-intel analyze --configure-agents` or another agent re-selection command.

## Embedding model selector

The Settings page now loads a backend-owned embedding model catalog and renders a pull-down instead of accepting arbitrary model text. The selected descriptor controls:

- the Hugging Face model ID loaded by the runtime;
- the expected vector dimension;
- the persisted embedding fingerprint;
- configuration validation and legacy alias normalization;
- vector-index compatibility and rebuild decisions.

The existing `all-MiniLM-L6-v2` short name is normalized to `Xenova/all-MiniLM-L6-v2` during migration.

## Persistent remembered sessions

Authentication sessions are now authoritative in the local users SQLite database instead of a process-local `Map`.

- normal login TTL remains configurable with `CODE_INTEL_SESSION_TTL_HOURS` and defaults to 8 hours;
- Remember me uses a 12-hour TTL;
- the browser receives a 256-bit opaque token, while SQLite stores only its SHA-256 hash;
- expiration slides only after more than 25% of the original TTL has elapsed;
- current user role and disabled state are checked on every session resolution;
- logout, password reset, user disable, and user deletion revoke server-side sessions;
- expired and revoked rows are removed in bounded startup and periodic cleanup batches;
- a session-store failure fails closed and does not authenticate a cookie.

An unexpired remembered login now survives stopping and restarting `code-intel serve`. Cookies issued by older builds have no corresponding persistent database row and therefore require one re-login after upgrade.

## Resilient GQL query results

Successful `POST /api/v1/query` responses now use one stable transport shape:

```json
{
  "kind": "aggregate",
  "nodes": [],
  "edges": [],
  "groups": [{ "key": "auth", "count": 2 }],
  "path": null,
  "executionTimeMs": 1,
  "truncated": false,
  "totalCount": 2,
  "format": "json"
}
```

The result-kind mapping is:

- `FIND` → `nodes`
- `TRAVERSE` → `traversal`
- `PATH` → `path`
- `COUNT` → `aggregate`

This fixes the reported Query Console crash where valid aggregate responses such as `COUNT function GROUP BY cluster` omitted `nodes` and caused render-time `undefined.length` failures in the Web UI.

The recorded exception signature was:

```text
Cannot read properties of undefined (reading 'length')
```

The failure was confirmed as a Query Panel render-time dereference, not an API transport failure. Plain `COUNT function` and grouped aggregate responses now both normalize to aggregate results with empty `nodes`/`edges` collections.

The release adds defense in depth:

- executor normalization for all successful GQL results;
- HTTP validation before serializing success payloads;
- structured `500` responses for malformed internal result shapes;
- Web runtime normalization for both new and legacy aggregate payloads;
- Query Console rendering by `result.kind`;
- local Query Panel error containment so result-render failures remain panel-scoped.

Compatibility notes:

- legacy aggregate responses with `groups` and scalar metadata but no `nodes`, `edges`, `path`, or `kind` are still accepted by the Web client;
- current truncated-query behavior remains `408` with `truncated: true`, and release validation now covers that status explicitly.

## Validation evidence

The final release candidate is required to pass all of the following on the same commit:

- Quality;
- Test;
- Code Intel PR Impact;
- Export Source Snapshot;
- Release Readiness.

Release Readiness verifies:

- package and lockfile version `1.0.10`;
- distributable build and npm pack validation;
- CLI version output;
- atomic first analysis and trusted index status;
- true no-op generation preservation;
- absence of leaked lock or staging state;
- Cursor-only setup selection and no project-file pollution;
- forced publication and trusted post-force index;
- dirty tracked and untracked source indexing;
- graph equivalence with a forced full rebuild;
- incremental embedding regressions;
- remembered login survives a server restart, logout remains revoked after another restart, and expired/unknown cookies are rejected;
- normalized GQL query route coverage for FIND / TRAVERSE / PATH / COUNT;
- grouped COUNT Query Panel regression coverage;
- browser-equivalent Web UI regression coverage via packaged SPA route smoke tests plus Query Panel component containment tests;
- zero high/critical npm audit findings.

## Rollback

A failed analysis does not replace `current.json`. The previously published generation remains available. By default, the current and previous successfully published generations are retained to support operational rollback.
