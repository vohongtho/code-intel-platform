# Code Intel v1.0.12

v1.0.12 extends the v1.0.11 engines rather than adding new ones. It makes ref snapshots queryable and portable, connects program analysis to PR impact and test selection, completes GraphQL and gRPC contract comparison, and adds semantic rename, architecture checks, resumable change workflows and authenticated offline runtime installs. All 22 roadmap items (F01–F22) in `openspec/changes/v1-0-12-release-program/proposal.md` are delivered. Two of them are narrower than their names suggest; see "What is opt-in or limited".

The per-feature detail, with flags and response fields, is in `CHANGELOG.md` under `[1.0.12]`. This page covers what changed for operators and what was validated.

## What is opt-in or limited

- PDG precision for `pr_impact` (F08) is opt-in. The mutation benchmark measured equal graph and PDG precision (0.33) with recall 1.0, so the promotion gate did not pass and `precision: "auto"` still selects `graph`.
- The Explore token reduction (median 33 % in `eval/run-explore-bench.mjs`) comes from a synthetic six-case fixture. It is not a measurement on real repositories.
- Rename apply works for TypeScript and JavaScript module-scope declarations only. The other 12 languages are preview-only, and files the tree-sitter grammar cannot fully parse block apply.
- Protocol facts for system flows are extracted from TypeScript and JavaScript literal keys only. gRPC bindings for Java, Go, C# and Python are published as unsupported capability rows.
- Runtime authenticity was run end to end on linux-x64. The linux-arm64, darwin-x64 and darwin-arm64 bundles were built and integrity-checked, not executed.
- Portable index packages are checksummed, not signed. Pass `--expect-sha256` with a digest from a channel you trust.

## Security fixes

- Logout did not revoke the server-side session; a copied cookie stayed valid until expiry, including across restarts. Fixed.
- Repo-scoped API tokens were not enforced on several current-index read routes and on group routes. Fixed.
- `taint-trace` accepted unbounded caller limits and had an exponential-backtracking string scan. Fixed.
- Dependency updates clear all high and critical `npm audit` findings. See the CHANGELOG for versions.

## Upgrading from 1.0.11

- Indexes are rebuilt on the first analyze: stable flow identity adds a producer fingerprint.
- The first `group sync` reports every contract as changed (`GROUP_CONTRACT_SCHEMA_VERSION` 1.0.12).
- Runtimes installed from 1.0.11 archives report `legacy-checksum`. Use `upgrade --bundle-dir` with the 1.0.12 release bundle to get a `verified` receipt.
- Clients that reused a session cookie after `/auth/logout` must log in again.

## Rollback

`code-intel rollback 1.0.11` on a self-contained runtime, or `npm install -g @vohongtho.infotech/code-intel@1.0.11`. Rollback refuses if persisted data declares a newer index schema; re-run `code-intel analyze` under 1.0.11 when prompted.
