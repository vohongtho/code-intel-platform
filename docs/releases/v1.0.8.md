# Code Intel v1.0.8

## Highlights

### Atomic index generations

`code-intel analyze` now runs against an isolated generation staging directory. The live index remains unchanged until graph, BM25, optional vector data and metadata have all been written successfully. Publication is completed by atomically replacing `.code-intel/current.json`.

The previous generation remains available after failed analysis or publication. Existing flat `.code-intel/{graph,bm25,vector}.db` layouts can be migrated to the generation layout.

### Index trust and freshness

Use:

```bash
code-intel index-status [repo-path]
code-intel index-status [repo-path] --upgrade-legacy
```

The result reports stable states: `trusted`, `stale`, `corrupt`, `missing` or `legacy`, together with artifact-level diagnostics and freshness reasons.

### Correctness-first changed-file handling

v1.0.8 detects committed, staged, unstaged, untracked, mtime-changed, and deleted source paths. Zero-change runs keep the incremental fast path. Any non-empty changed/deleted source set performs a clean full graph rebuild so unchanged callers, importers, and inheritors are re-resolved and generated clusters/flows are recreated from a clean baseline.

This intentionally prioritizes correctness over partial-rebuild latency. Release validation requires canonical graph equivalence with a forced clean rebuild.

### Truthful and explainable search

Search responses distinguish:

- `requestedMode`: what the caller requested;
- `actualMode`: what actually executed;
- `searchMode`: backward-compatible alias of `actualMode`;
- explicit fallback reasons: `VECTOR_INDEX_UNAVAILABLE` for missing/unbuilt/empty vector state and `VECTOR_QUERY_FAILED` for execution errors;
- optional execution explanation and per-result lexical/vector/RRF score evidence.

Request explanation metadata with `explain: true`.

### Hard context token budget

The context builder now enforces `maxTokens` across the complete returned document. Responses include measured block token counts and stable `truncatedBlocks` metadata.

### Change Context Pack

Build a single coding-agent package containing changed symbols, blast radius, risk, coverage gaps, test suggestions and bounded source context:

```bash
code-intel change-context . --files src/a.ts,src/b.ts --max-tokens 3000
code-intel change-context . --diff-file change.diff
```

Dedicated transports use the same shared service:

```bash
code-intel change-context-mcp .
code-intel change-context-http . --host 127.0.0.1 --port 30128
```

HTTP endpoints:

- `GET /health`
- `GET /openapi.json`
- `GET /api/v1/index-status`
- `POST /api/v1/change-context`

MCP tools:

- `change_context`
- `index_status`

## Compatibility

- Existing `searchMode` consumers continue to work.
- Legacy search input `hybrid` is normalized to `auto` and marked deprecated.
- Existing `detect_changes`, `pr_impact` and `suggest_tests` behavior is retained; `change_context` composes the same analysis into one response.
- Legacy flat index files remain readable until migration or the first successful generation publication.

## Validation

The release branch is gated by:

- TypeScript builds for shared, core and web;
- complete core test suite;
- npm audit high/critical gate;
- generation publication and failure rollback tests;
- index trust tests;
- hard token-budget tests;
- search explanation, score-evidence, and vector fallback contract tests;
- unchanged caller/importer/inheritor regression coverage;
- canonical changed-run versus forced-rebuild graph equivalence, including cluster and flow state;
- change-context and staging-path tests.
